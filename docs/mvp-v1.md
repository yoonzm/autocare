# 一期 MVP 范围(限时免费、无会员端、无线上支付)

目标:不丢核心功能,先快速上线。一期只发布**商户端 App**(老板与员工同一个 App),通过收缩发布范围实现,不重写、不删除已有代码。

## 发布范围

| 端 | 一期 |
| --- | --- |
| 商户端 Flutter App(老板 + 员工) | 上线,唯一交付物 |
| 会员端小程序 `apps/member-mini` | 不发布。`member-v1` 云函数保留,不对外承诺 |
| 店员端小程序 / 桌面端 | 不做(员工已并入商户端) |
| 运营后台 `apps/admin` | 仅内部使用:开账号、查短信、注销账号、套餐配置 |

## 一期包含

**老板侧**
- 注册 / 登录 / 忘记密码 / 账号注销(短信用助通真实渠道)
- 服务项目、会员卡种、次卡套餐、工位与营业时间、新店默认模板
- 会员与车辆、车牌扫码找会员
- 预约(商家代客创建、改约、取消、日程)
- 开单与收银(选择服务;会员卡、储值、次卡抵扣)
- 会员跟进、回访、挂单、反馈
- 库存:商品、入库、出库、盘点、供应商(与开单无关联:订单明细只关联服务,开单不扣库存)
- 支出:记账、分类、预算、分摊
- 首页与基础经营统计
- 员工档案、角色、角色权限、提成方案、施工记录、停用 / 转交 / 启用

**员工侧(需独立可用)**
- 手机号验证码登录、选择身份、加入门店
- 技师:工作台、任务、更新进度、完工提交、业绩提成、消息
- 前台:今日到店、预约、预约结算
- 权限由 `merchant-v1` 的 `staff_gate.ts` 逐请求校验

## 无线上支付的处理

- 收银只记录客户的支付方式(现金、微信收款码、支付宝、刷卡),由商家线下收款,系统只记账。
- 会员充值、办卡、买次卡同样为线下收款后录入。线上充值仍为 TODO 并明确阻止,不返回假成功。
- 不出现支付进件、收款配置、发票、退款到账等页面入口。

## 限时免费:应用内不出现任何订阅内容

一期不做订阅、套餐购买和续费。产品对用户的口径只有一句:**限时免费**。

- **注册完成页**显示"限时免费",替换原有的"专业版 · 试用至""试用结束后怎么办""看套餐"等试用与套餐文案。
- 注册即开通完整功能,没有到期时间,不做到期提醒,不进入只读模式。
- **移除应用内全部订阅入口和页面**:订阅与套餐页、确认订单、续费弹层与成功页、试用中 / 即将到期 / 已过期提示、店员"套餐已到期"页、发票、优惠券、设置与首页里的套餐信息和续费入口。
- 其他页面里出现的试用、订阅、套餐文案同步清理(例如账号注销页、条款页、更新日志)。
- **后端**:新注册账号自动开通一个内部的"限时免费"权益(完整功能、无到期)。套餐表、账号订阅表和既有同步触发器作为内部权益机制保留,不向客户端展示。商户端不再提供订阅与模拟支付入口;`subscription_catalog`、`subscription_simulate` 不对一期客户端开放。
- 员工的"套餐到期拦截"在一期不会触发,相关逻辑和页面保留但不可达。
- 以后收费时,再单独设计订阅入口、套餐与支付,并重新启用上述后端接口。这是后续单独审批的事项。
- 该方案取代原先"套餐配置里加限时免费开关"的想法,后台套餐配置本期不改。

> 这是对 `docs/subscriptions.md` 与 AGENTS 中账号订阅、模拟支付两条约束的一期收缩,需要你确认后再同步修改约束文件。上述页面多为生成页,改动通过 `tools/design_to_flutter.py` 进行,不手改 `gen/`。

## 一期新增开发

1. 移除订阅:注册完成页改为"限时免费",清理应用内订阅相关入口与页面,后端注册自动开通内部限时免费权益。
2. 员工端会员简况与扫码找会员:需要后端脱敏查询接口,核销需车主确认。
3. 员工邀请页二维码:接下载链接生成真实二维码,否则一期删除二维码。
4. 修改密码(商户端与员工端)。

## 一期不做:直接删除代码,不用开关

一期不实现的功能直接从代码里删除,不保留开关或隐藏入口;二期需要时从 Git 历史恢复或重新开发。

- 多门店切换与新增门店
- 消息通知、短信营销、优惠券
- 数据备份、导出
- 支付进件、收款配置、发票、渠道配置、绑定
- 订阅:套餐、续费、试用 / 到期提示、到期页
- 会员端小程序 `apps/member-mini` 与 `member-v1` 云函数;店员端小程序、桌面端占位

删除原则:
- 生成页不手改 `gen/`,在 `tools/design_to_flutter.py` 中移除对应页面后重新生成。
- 已应用的数据库迁移不能修改。一期只删代码,不删库表和数据;如需清理表结构,另写新迁移并单独批准。
- 删除同时清理路由、导航跳转、测试、文档和 CI 配置中的引用。

## 节奏

- 第 1 周:冻结范围,批准删除清单,删除不做的代码,移除订阅并改为限时免费。
- 第 2 周:新增开发(员工端会员简况与扫码、修改密码、邀请二维码);走通"注册→建服务→录会员车辆→预约→开单→库存与支出→员工完工与结算"全流程并补自动化测试;并行办签名、短信模板、商店资料。
- 第 3 周:3 到 5 家真实门店内测,修阻塞项,提审。
- 范围冻结后,新需求一律进二期清单。
