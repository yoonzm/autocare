# 后端接入标准与 V1 范围

## 不变的前端

设计稿及现有 Flutter 页面、导航和文案保持原样。后端接入不能重画登录页、改成邮箱表单，也不能以新的列表页替换已有服务项目或会员卡种页面。生成页面位于 `apps/merchant/lib/pages/gen/`，不要手工编辑；如现有组件缺少数据绑定，应在非生成代码的适配层接入，无法可靠接入时保留界面并标 `TODO`，不可伪称已完成。

## 后端边界

Supabase Auth 管理身份；Edge Functions 执行注册开通、权限判断、服务项目和会员卡种的业务规则及写操作，供未来小程序、桌面端和后台端复用。客户端不能直接写业务表，也不能持有 `service_role` 密钥。数据库 RLS 是最后一道隔离边界。每个云函数验证身份、输入及门店归属后才操作数据库。生产环境不得启用固定验证码或其他短信 mock。

## V1 交付范围

1. 商户注册/登录：保留当前手机号、验证码、密码界面。短信发送暂以开发环境后端 mock 代替，真实短信供应商及生产级手机号认证标 `TODO`。
2. 服务项目：后端提供按门店隔离的读取和维护能力；接入现有页面可可靠承载的动作。
3. 会员卡种：同上；不实施会员资料、办卡、消费等业务。

所有未接通动作必须在代码及 PR 描述标明 `TODO`，并保留原型可浏览性，不把 mock 数据呈现为真实营业数据。
