# 后端接入标准与 V1 范围

## 不变的前端

设计稿及现有 Flutter 页面、导航和文案保持原样。后端接入不能重画登录页、改成邮箱表单，也不能以新的列表页替换已有服务项目或会员卡种页面。生成页面位于 `apps/merchant/lib/pages/gen/`，不要手工编辑；如现有组件缺少数据绑定，应在非生成代码的适配层接入，无法可靠接入时保留界面并标 `TODO`，不可伪称已完成。

## 加载与反馈

接入后端的页面必须按 [前端加载与反馈规范](frontend-loading-feedback.md) 实现：骨架屏 / 空数据 / 错误重试 / 按钮 loading / Toast，以及统一超时、读请求重试和 401 处理。该文档末尾列出了已落地的页面和仍未做的部分。

## 后端边界

Supabase Auth 管理身份；Edge Functions 执行注册开通、权限判断、服务项目和会员卡种的业务规则及写操作，供未来小程序、桌面端和后台端复用。客户端不能直接写业务表，也不能持有 `service_role` 密钥。数据库 RLS 是最后一道隔离边界。每个云函数验证身份、输入及门店归属后才操作数据库。生产环境不得启用固定验证码或其他短信 mock。

## V1 交付范围

1. 商户注册/登录：保留当前手机号、验证码、密码界面。短信发送暂以开发环境后端 mock 代替，真实短信供应商及生产级手机号认证标 `TODO`。
1.0 新门店初始化：注册成功时由云函数给新门店生成设计稿里的示例数据，不另造数据。服务项目按所选主营业务取设计稿服务项目页的 8 个，再加上设计稿选择服务弹层里出现、次卡套餐需要的“镀晶养护”（¥1,280）和“空调杀菌”（¥98），共 10 个（洗车美容 → 洗车、内饰；镀晶镀膜 → 镀晶镀膜；隐形车衣 → 贴膜；设计稿没有改色膜、保养维修的示例，只选这两项时服务项目为空；发动机舱清洗在设计稿里是已下架状态，初始化时同样为下架；镀晶养护归在镀晶镀膜，空调杀菌归在内饰）。卡种取设计稿卡种列表里的 4 个（黑金卡 9 折、金卡 9.5 折、银卡 9.8 折、普通会员原价）。次卡套餐取设计稿次卡套餐列表的 6 个（精致洗车年卡 ¥1,080、精致洗车 10 次卡 ¥580、内饰深度清洁 6 次卡 ¥1,380、镀晶养护 3 次卡 ¥2,980、空调杀菌 4 次卡 ¥380、已下架的新客体验卡 ¥99），只创建其包含的服务已存在的套餐：选了洗车美容、镀晶镀膜才分别得到对应套餐，默认三项主营业务全部 6 个都有，只选隐形车衣、改色膜、保养维修则没有；原价由服务单价 × 次数自动汇总，不单独存储。设计稿里的会员人数、“本月 N 单”等是统计示例，不是初始数据。数据定义见 `supabase/functions/merchant-v1/defaults.ts`。
1.1 忘记密码：登录页（密码登录）的“忘记密码？”和账号与安全 → 修改登录密码里的“忘记当前密码？用验证码重置”共用同一套 3 个页面（验证手机号 → 设置新密码 → 重置成功），两个入口都手动输入手机号。重置后所有设备的登录状态失效，已登录的设备也要重新登录；验证码同样是开发环境后端 mock，生产需接入短信服务。
2. 服务项目：按门店隔离的列表、新增、修改、删除；V1 保存名称、分类和门店价。会员折扣、工时、预约等规则暂不接通。
3. 会员卡种：按门店隔离的列表、新增、修改、停用（软删除）。已保存的配置：名称、项目折扣（整张卡统一折扣系数）、卡面颜色、升级条件（单次充值满 / 累计消费满，可留空）、积分倍率、生日礼、预约优先排期、有效期，以及门店的两项通用规则（充值或消费自动升级 / 储值余额可退款）。这些只是**配置**；折扣如何用于开单、积分如何累计、何时升级、生日礼如何发放、预约如何优先、有效期如何计算，依赖订单 / 会员 / 预约模块，尚未实施。会员人数、办卡同样不在此范围。
5. 会员（核心维护）：按门店隔离的会员列表（按姓名 / 手机号 / 车牌搜索、按卡种筛选、各卡种会员数）、办卡（新增会员）、修改资料、删除、名下车辆的新增 / 修改 / 删除。办卡由云函数 `create_member` 在一个事务里建档并发放起始卡种（门店里没有升级门槛的卡种，即“普通会员”，客户端不能指定卡种），可同时登记一辆车；手机号在本店唯一，车牌在本店唯一，推荐人必须是本店已有会员，称呼 / 来源 / 生日 / 车牌 / 车架号等都由云函数校验。删除为软删除并移除车辆，卡种下还有会员时不能停用。**暂未接入**（`TODO`，都依赖其他模块）：储值余额与充值（开卡成功页、详情页的“去充值”“余额充值”只提示）、累计消费 / 到店次数 / 积分 / 最近到店、按充值或消费自动升级、次卡购买与使用、消费与充值记录、开单、微信绑定与通知、回访、发送通知、调整卡种与积分、高级筛选（余额 / 到店 / 次卡状态 / 车辆与项目）、列表分页（目前最多取 100 条）。这些位置显示“—”或提示未接通，不造数据。
4. 次卡套餐（配置部分）：按门店隔离的列表、新增、修改、删除（软删除）。已保存：名称、包含服务及每项次数、套餐售价、有效期、每人限购、适用车型、是否在会员小程序展示、说明、上架状态；原价合计、相当于单次、省多少 / 折扣由客户端按已选服务和售价即时计算，仅用于展示，存储的只有售价与明细。服务项目被套餐引用时不能删除。依赖订单 / 会员模块、**尚未接入**的部分（`TODO`）：列表上的“已售 N”与经营概览（本月营收 / 售出 / 在用 / 将到期，目前显示“—”）、会员购买次卡、开单核销、延期、退款、套餐详情 / 已售名单页面；“每人限购”“适用车型”目前只是配置，购买环节执行校验要等售卖接口实现。

所有未接通动作必须在代码及 PR 描述标明 `TODO`，并保留原型可浏览性，不把 mock 数据呈现为真实营业数据。
