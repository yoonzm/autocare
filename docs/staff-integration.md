# 员工模块接入（员工与权限）

用户已批准把员工模块的全部页面接入真实后端：员工列表 / 新增 / 编辑 / 详情、邀请、角色权限、提成方案、施工记录、停用 / 转交 / 启用、已停用详情。界面以设计稿为视觉基线，历史生成页位于 `apps/merchant/lib/pages/gen/`，接后端的模板保留既有视觉。原派生脚本已移除；后续按 `docs/frontend-guidelines.md` 第 18 节迁移并直接维护源码。

12 张设计稿页面的结构、文案、颜色与交互布局保持原样（已用 Chromium 设计稿截图与 Flutter 渲染逐页比对）。两处按最新设计稿修正了生成页过期的颜色：员工列表右上角「+」、邀请页「完成」为主色蓝底。

## 真正接通的动作（`merchant-v1` 的 `staff_*`，迁移 `202611090001_staff.sql`）

| 动作 | 说明 |
| --- | --- |
| `staff_list` / `staff_get` | 员工列表（含角色人数、本月台次、施工状态、邀请状态）、员工详情（本月提成、最近施工、进行中订单、各服务项目提成） |
| `staff_save` | 新增 / 编辑员工：角色（店长 / 前台收银 / 施工技师）、手机号唯一、擅长项目、固定工位、入职日期。技师同步写入预约排班资源，预约逻辑不变；原 `appointment_resource_save` 不再接受技师 |
| `staff_status` | 停用 / 启用。停用技师若有进行中或待到店的预约，必须同时指定接手技师（`transfer_to`），事务内转交并复核时段冲突；停用后排班资源同步停用，历史记录与提成保留；记录操作人与时间 |
| `staff_commission_save` | 提成方案：跟随项目 / 统一比例 / 按项目自定义。仅对之后完工的订单生效 |
| `staff_records` | 施工记录（本月 / 上月 / 全部）：台次、提成、平均用时、明细 |
| `staff_permissions_save` | 逐店保存前台收银、施工技师的权限开关；店长权限由系统固定；数据库提供 `staff_has_permission(store, role, permission)` 供员工端和后续接口复用 |
| `staff_invite` | 生成 7 天有效的邀请令牌（只存 SHA-256），返回邀请链接；重新生成会作废旧邀请 |

提成：服务项目新增结构化提成（`commission_type` 比例 / 固定、`commission_value`）；既有项目与新建项目按描述里的“提成 8%”“提成 ¥60/单”解析一次。预约订单结算（回填 `orders.appointment_id`）时由触发器按当时规则写入 `staff_commissions` 快照，之后改规则不重算；比例按实收（扣除会员折扣后的占比），固定金额按数量。仅预约结算的订单有施工技师；无预约的散客开单没有技师归属，不产生提成。

## 店长维护门店

店长可维护当前会话所属门店的名称、电话、地址及门店照片（`store_update`、`store_media_list/upload/remove`）。网关、图片处理器和数据库同时校验；数据库从有效会话解析门店，照片校验在职店长与登录用户的绑定，不接受跨店操作。新增、切换、归档、恢复门店仍仅老板可用。迁移：`202611200005_manager_store_maintenance.sql`，需与 `merchant-v1` 一起发布；App 页面及交互不变。

## 店长管理普通店员

店长默认具有 `staff_manage`，可新增、邀请、编辑和启停当前门店的前台/技师。新增店长、将普通店员提升为店长、编辑自己或其他店长、角色授权及提成设置仍仅老板可操作。启停保留预约未完工检查和转交流程；未完成的挂单施工任务须先完工或重新分配技师，再停用账号或将技师改为其他角色。

所有员工写入经 `manage_store_staff`：由已校验的登录用户和会话解析当前身份及门店，事务内锁定员工并校验原角色与新角色，客户端不能指定身份或跨店操作。数据库入口只授予 `service_role`。发布需先应用 `202611200007_manager_staff_management.sql`，再更新 `merchant-v1`；App 根据权限隐藏不可操作入口，页面原有样式不变。邀请沿用已有激活流程，未配置的邀请链接仍明确返回未接通（短信邀请已接通通知短信接口）。
