# 开支模块真实接口接入

## 界面保持

保留开支列表、新增、详情、预算总览、总预算编辑、分类预算及追加预算弹层的既有设计和导航。`gen/` 未修改；`apps/merchant/tools/bind_expenses.py` 从现有设计生成独立绑定模板，只替换数据、表单状态与事件。日期分组、分类预算行和历史图表按真实数据生成。未登录引导登录，无 mock 回退。

## 已接通

- 按月查询、固定/变动分类筛选、分类构成、开支与预算汇总；营收取真实收款订单金额。
- 新增、编辑、删除开支，付款状态、日期、分类、账户、收款方及备注持久化。删除重复开支同时停用后续重复计划。
- JPEG/PNG 凭证上传、移除关联和查看；每笔最多五张、单张 5MB，私有 Storage 桶，通过所属门店校验后返回五分钟签名地址。
- 总预算及分类分配、复制上月、按上月预算/实际开支权重分配、历史图表、分类阈值与超支策略、追加总额、未分配余额和分类间调剂。
- 月度重复开支生成待支付记录；月底日期自动夹取有效日。预算延续、分类重复和剩余结转在后端执行。每日上海时间 00:05 定时处理，读取/写入时补偿执行，唯一键防重复。
- 入库勾选同步开支后，与库存事务一起生成材料采购记录；挂账生成待支付记录。盘亏按真实成本生成损耗记录。库存来源金额、日期和分类不可独立修改或删除，凭证、备注和付款状态可编辑。

## 接口与业务保护

`merchant-v1` 新增 `expense_board/get/save/delete/suggest/budget_save/budget_adjust/upload/voucher/source`。

每个动作通过 `storeFor` 验证登录和门店所有者。数据库开启 RLS，浏览器不能直接写表或执行业务函数。金额、预算分配、禁止超支、调剂可用余额、版本冲突、来源锁定及库存同步由服务端执行。门店事务锁串行化预算与开支，request ID 防止重放；失败整体回滚。

目前只有店主账号可以执行接口，因此“店主确认”策略以店主身份授权为前提；员工审批流未接入。待支付记录也计入月度开支与预算占用，重复计划生成不会发起实际支付。移除凭证只解除关联，不立即删除私有对象。

## 外部依赖与部署

- 手机推送尚未接入，开关明确提示，不伪造订阅成功；预期后续接入通知订阅与发送接口。阈值设置可以保存。
- 付款状态是记账字段，不调用支付服务。库存送货单上传入口仍不独立上传，可在开支编辑中补充凭证。
- 依次执行 `202611030005_expenses.sql`、`202611030006_expense_vouchers.sql`、`202611030007_expense_automation.sql`，再部署 `merchant-v1`。最后一个迁移需要 Supabase 的 pg_cron 扩展。
- 本次未执行远端迁移或云函数部署。Storage、定时任务与真机相册/相机需部署后用真实账号验证，不将本地测试视为线上联调完成。
