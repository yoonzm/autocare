# 商户图片上传迁移（2026-11-13）

本次用户批准将个人头像、车牌识别之外的图片上传统一为 `AppImageUploader`，同时接通门店与施工照片真实后端。

图格、圆角、文字、计数和换行统一采用组件库规范。移除旧三槽布局、文件名附件列表、重复标题、无真实数据的入库图标占位和照片 TODO。门店资料照片改为只读网格。其他表单、导航、头像与车牌识别保持现有实现。

## 组件职责

`AppImageUploader` 只渲染受控数据，新增 `pending`、可空 `progress`（未知进度用标准 spinner）、`enabled`、`readOnly` 和 `helper`。图片加载失败有占位；上传中禁止重复操作，失败图片可移除或重试。

`UploadGallery` 负责选图、异步状态、预览与晚到响应保护；业务通过显式回调提供加载、上传和移除。`VoucherGallery` 保留原 expense 接口与表单路径；`MediaApi` 调用新照片接口。反馈继续由页面实例持有草稿，不提前上传。

## 新接口与权限

- `store_media_list/upload/remove`：仅当前店主；目标门店由已验证会话决定。
- `staff_task_photo_list/upload/remove`：读取要求 `order_view_own`，写入要求 `progress_update`；数据库再次确认当前门店、任务分配的技师、员工启用状态及任务状态。
- 上传参数 `data` 为 JPEG/PNG base64，最多 5MB；施工接口还需 `target_id`。客户端不能指定门店、员工或存储路径。
- 上传 `X-Request-Id` 为 UUID，数据库锁定目标并限制数量，绑定图片内容摘要；相同编号相同内容重试不会新增图片，不同内容拒绝。移除接收图片 `id`，幂等执行。
- `merchant-media` 为私有桶；表启用 RLS，客户端角色无读写或 RPC 执行权限。后端仅对可见图片生成 300 秒签名 URL，预览时重新签名。
- 删除先写墓碑再移除存储；失败明确返回错误并可重试。晚到上传不能复活已删除记录。失败图片移除会清理服务器占位。
- 中断后无人恢复的 pending 占位在新上传时按 24 小时过期释放额度。存储孤儿文件的定期清理尚无后台任务（TODO：增加定期核对 `merchant_media` 与私有桶的清理作业），不影响可见图片归属和限额；不宣称不存在存储孤儿。
