# 账号套餐与订阅：临时模拟支付

用户明确批准订阅/续费暂不连接支付渠道，提交后走后端模拟支付成功，再执行真实权益激活。此例外仅适用于账号套餐，不适用于收银支付、退款、发票、自动续费或其他资金操作。

## 真实数据与界面

套餐列表、确认订单、续费弹层、当前订阅和成功回执均读取后端；保留原型布局。基础/专业套餐沿用后台已配置价格，新增原型中的旗舰版（初始年费 6990 元，10 家门店），后台 `PlanKind` 同步支持旗舰版。客户端不提交支付金额，原型的价格、优惠券和订单号不作为业务依据。

套餐配置新增 `monthly_fee` 和 `quarterly_fee`，初始月价为年价的 1/10、季价为三个月月价的 95%（金额四舍五入到分）。后台原有年费编辑器更新年费时同步生成月/季价和新版本快照。12 个月采用年费；门店名额、员工名额、功能标志由后端提供。未接通的通知、导出、跨店会员和专属服务不承诺为可用能力。

`subscription_catalog` 返回可购套餐、账号当前订阅、订阅修订标识及模拟标记。`subscription_simulate` 接受套餐、套餐版本、1/3/12 个月、订阅修订标识、subscribe/renew 和请求头幂等编号。账号、会话从已验证令牌取得，不接受客户端指定付款人或权益价格。

## 成功事务

1. 锁定账号与账号订阅，验证会话和账号状态。
2. 查询已处理请求：相同正文返回原回执，编号复用但正文不同则拒绝。
3. 校验订阅修订标识、套餐版本、周期和门店名额。续费仅允许当前套餐；试用用户先选择付费套餐。
4. 根据后端价格创建 `platform_orders`：`status=paid`、`pay=模拟支付`、`simulated=true`，写入真实订单 ID 和时间。
5. 更新 `account_subscriptions` 为新套餐版本、有效期、`source=simulation`。既有同步触发器更新全部门店兼容镜像，账号下所有门店共享权益。
6. 保存请求和回执，同一事务提交。客户端收到回执后才进入成功页并刷新账号订阅，不在前端直接修改套餐来冒充开通。

续费从 `max(现在, 原到期时间)` 顺延；订阅/升级即时切换套餐权益，保留原剩余时间，再增加所购周期，不计算补差价，不发放原型中的虚构优惠券。降级若门店数超限则拒绝，需先归档。前端价格或订阅过期时刷新目录，要求用户核对后明确再次提交，不自动按新价格重付。

失败保留确认页和输入；相同内容重试复用请求编号。按钮 loading、防连点与错误提示使用统一组件。成功页显示后端金额、期限、订单号，并明确标记“模拟支付（暂不扣款）”。未开通自动续费或真实发票。

## 统计、审计与后续真实支付

模拟订单保留在后台订单列表，支付方式标明模拟；真实营收、实收及 MRR 汇总排除 `simulated=true`，不能用模拟数据冒充现金收入。订阅人数按实际已生效账号权益统计。实际支付渠道接入前，需要确认跨套餐补差价/剩余价值折算规则；当前保留剩余时长仅用于模拟阶段。实际支付渠道接入后，应移除商户可直接调用的模拟入口，由已验证支付回调调用权益激活事务，继续保留模拟订单来源标识，不能将历史模拟订单转成真实收款。
