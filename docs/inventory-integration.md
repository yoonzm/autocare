## 已接通

- 首页：真实商品、分类、SKU 数、按批次成本统计的库存总值、低库存与 30 天内有效期预警；保存后刷新。
- 商品：在“添加商品”中新增资料；详情供应商字段进入资料编辑，支持名称、SKU、分类、单位、规格、货位、供应商、安全库存。存量成本只能通过库存单据变化。
- 入库：多商品、最多三位小数数量、成本单价、批次有效期、供应商、日期、运费、付款方式记录、草稿保存及恢复。
- 出库：多商品、领用/报废/退供应商/内部使用分类、备注、先进先出扣减；不足库存整单失败。
- 盘点：全部/未盘/有差异筛选、实盘数量（支持零）、暂存恢复、提交差异单；并发变化拒绝提交，刷新受影响商品后要求重新盘点。
- 详情：真实批次、出入库流水及类型筛选；进入入库/出库时带入当前商品。
- 成本预览由 `inventory_quote` 后端计算，最终提交在事务内重新计算，避免以客户端金额记账。

## 接口与安全

`merchant-v1` 动作：`inventory_list`、`inventory_get`、`inventory_create`、`inventory_update`、`inventory_draft`、`inventory_quote`、`inventory_document`。

所有动作通过 `storeFor` 验证当前门店。数据库表启用 RLS，客户端只有所属门店读取权限，写入及成本规则由云函数调用受限数据库函数执行。整单提交对商品按 ID 顺序加锁；批次扣减、库存、流水、单据状态原子提交。单据 UUID 是持久幂等键，网络重试不会重复入出库；草稿用 revision 防覆盖，盘点用商品 version 防覆盖。

迁移顺序：`202611030003_inventory.sql` → `202611030004_inventory_documents.sql`，然后部署 `merchant-v1`。第二个迁移将库存升级为小数、引入整单与批次，并禁用第一版单商品变更函数的调用权限。

## 2026-11-05 盘点与扫码补齐

- 新建盘点保留设计稿的范围、方式卡片：全部商品、按分类、按货位；盲盘、暂停出入库设置。范围由后端生成快照，每店仅一张进行中的盘点单，支持最多 5000 项。
- 录入页支持零数量、小数单位、全部/未盘/有差异筛选、右上暂存、扫码定位商品。盲盘的录入接口不返回系统数量、成本和版本，差异在结果确认页展示。暂存保存所有范围行，未盘为 null。
- 结果确认由后端计算 FIFO 成本；确认提交才原子调整已盘商品、生成调整流水并登记盘亏开支。未盘商品不变。提交后不可修改，重放不会重复扣库或记开支。
- 不暂停出入库时，盘点提交会检查库存版本；有冲突时可以刷新快照，清空变化商品的实盘数后重新盘点。暂停模式由数据库门店锁与库存事务入口强制执行，结束或取消后解除，其他库存单据仍可暂存。
- 盘点单页区分进行中和历史，显示实盘进度、已提交/已取消状态及净差异；点击继续盘点或查看结果。取消不会调整库存。
- 扫码查询使用 `mobile_scanner` 的相机条码/二维码识别，后端精确匹配本店 SKU/商品条码；重复识别期间禁用再次提交，查不到或编码歧义有真实错误反馈。首页进入商品详情，商品选择勾选商品，入库扫码加入明细，盘点扫码定位范围内商品。无相机/权限失败可手动输入，Windows/Linux 使用手动输入。
- 商品资料新增可选“商品条码”；条码在门店内唯一，SKU 与其他商品条码交叉重名时查询明确拒绝歧义。相机不上传图片，不使用随机识别结果。

新增迁移：`202611050002_inventory_counts_scan.sql`，在 catalog 迁移之后执行，再部署 `merchant-v1`。`inventory_counts` 快照表启用 RLS 且不向客户端授予直接读取权限，所有盘点动作经门店鉴权云函数。现有旧版 `inventory_documents.kind=check` 单据不删除、不改账，新盘点列表同时展示新会话和旧单据，旧草稿可继续原流程或作废；存在旧草稿时后端禁止再新建盘点。
