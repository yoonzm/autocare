# 次卡套餐经营统计

保持现有套餐列表、经营概览、编辑入口、导航及深浅色设计；生成页没有手工修改。

真实接通 `merchant-v1` 的 `package_stats`：云函数解析登录会话和当前门店，员工必须具备 `stats_view_store` 权限。无统计权限仍可按原权限读取套餐目录，前端不请求或展示销量和概览。数据库 RPC `merchant_package_stats` 仅限 `service_role`，不向客户端开放按任意门店查询。

统计口径：

- 本月次卡营收：北京时间自然月月初至当前的售卡实付金额，减去本月发生的次卡退款；跨月退款扣在退款月，允许出现负净额。包含储值余额购买，属于业务记账，不代表渠道核验到账的现金收入。
- 较上月：当前月截至现在的净额与上一个完整自然月净额比较；上月净额不大于零时显示 `—`。
- 本月售出：当月真实购买记录数；后续退款不抹除售出历史。
- 在用次卡：未退款、有剩余次数，且永久有效或尚未到期。
- 将到期：在用卡中，到期时刻大于当前时刻且不晚于未来 7 天的卡。
- 列表已售：按原套餐 ID 汇总累计购买记录，包含后来退款的记录。历史已下架、软删除套餐的购买记录仍计入总览，不因目录删除消失。

后端直接 SQL 聚合，不下载全量售卡列表，不受 REST 默认 1000 行限制。首次加载用统一骨架及错误重试；刷新失败保留已加载数据并提示，不以零值或示例数代替失败。

部署顺序：先应用 `202611100004_package_stats.sql`，再更新 `merchant-v1` 的入口、`package_stats.ts`、权限目录。客户端需使用包含此数据绑定的新构建。没有接入真实支付渠道，也没有新增退款、通知等动作。

验证：`supabase/tests/package_stats.mjs` 覆盖空店、超过 1000 条、金额、退款、月份和时区边界、到期与用完状态、门店隔离及 RPC 授权；`staff_gate.test.ts` 覆盖统计权限；`apps/merchant/test/packages_test.dart` 覆盖真实数据展示、加载、失败重试、刷新失败、无权限、零值和历史售卡。
