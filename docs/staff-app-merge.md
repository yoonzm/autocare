# 商家端 / 店员端合并（一个 App，多身份）

设计稿把店员端并入商家端：同一个 Flutter App（`apps/merchant`），同一套验证码登录，登录后按身份分流。用户已批准接入真实后端；界面仍以设计稿为视觉基线，历史生成页位于 `apps/merchant/lib/pages/gen_st/`，接后端的模板保留既有视觉。原生成器与派生脚本已移除；后续按 `docs/frontend-guidelines.md` 第 18 节迁移并直接维护源码。

## 身份与权限

- 一个手机号 = 一个认证账号；老板身份来自 `merchant_accounts`，员工身份来自 `store_staff`（按手机号匹配，可跨多家门店）。登录后：没有身份 → 登录失败页；一个身份 → 直接进入；多个 → 选择身份；首次员工身份 → 「加入门店」确认。
- 当前身份按登录会话保存（`staff_sessions`），「我的 → 切换身份」重新选择。老板 / 店长使用商家外壳，前台收银 / 施工技师使用员工外壳（技师 4 个 Tab：工作台 / 任务 / 会员 / 我的；前台：工作台 / 预约 / 会员 / 我的）。
- 权限目录 27 项（设计稿「权限矩阵」），角色默认值 + 老板在「角色权限」页调整（页面仍只展示原有 10 个开关，其余项取角色默认值；设计稿标「—」的项对该角色永远关闭）。**权限由 `merchant-v1` 的 `staff_gate.ts` 逐请求校验（默认拒绝）**，前端 `Access.can()` 只决定显示什么。
- 套餐到期：老板可进入续费，员工看到「套餐已到期」页；员工被停用后其会话立即失效。技师预约只看自己名下的；员工读取门店信息时不含价格。

## 真正接通的动作

| 页面 | 动作（`merchant-v1`） |
| --- | --- |
| 登录 / 选择身份 / 加入门店 / 登录失败 / 暂无权限 / 套餐到期 | `identity_list` / `identity_select` / `identity_join` / `identity_context` |
| 技师工作台、前台工作台、我的 | `staff_home`（含未读消息数；我的的「切换身份」只对多身份账号显示） |
| 我的任务 / 任务详情 | `staff_task_list` / `staff_task_detail`（只返回派给自己的预约） |
| 更新进度（弹层） | `staff_task_progress`：已完成节点数 1–3，只能向前，仅施工中的任务 |
| 完工提交 / 已完工 | `staff_task_finish`：任务进入「已完成」，通知前台与店长收银；返回今日累计预计提成 |
| 业绩提成 | `staff_perf`：本月提成 / 完成单 / 业绩、近 7 天、明细（来自 `staff_commissions` 快照） |
| 消息 | `staff_messages` / `staff_messages_read`；新任务、车主到店、提成已更新、权限已调整由数据库触发器写入 |
| 今日到店 | `staff_arrivals`（需「今日到店」权限） |

## 与设计稿的差异（因没有数据来源，不造假）

- 任务详情：「宝马 5 系 · 黑色」改为预约时间窗（预约只登记车牌）；「施工照片」显示 0 张，「添加」提示 TODO；完工页去掉「完工照片 6 张」和「耗材」行（照片上传、领用耗材未接通）。质检清单是技师确认语，点「确认完工」即提交。
- 完工页 / 已完工：文案改为「已通知前台收银，结算后计入本月提成」；提成标注为「预计提成」「今日累计预计」（实际提成在预约结算时按实收落快照）。
- 「我的」好评率显示「—」；联系店长、修改密码提示 TODO。
- 业绩页「提成比例」为本月提成 / 本月业绩的综合比例，不是配置的方案比例。
